# Sustained extraction durable recovery acceptance

Tests/docs successor to merged PR97 (`8fd91d5167b941a7939971663d04c8fad6f2b9ac`). `sustained_extraction_recovery_test.gd` inherits its actual authenticated client equipment/transport and finite conservation helpers. It picks up the existing owned canister, equips/selects the existing extractor and approaches iron through the bounded shell movement sampler. No inventory, resource, permission or canonical position grants are injected.

The client requests two cycles into its 2 kg carrier. After one completed cycle, 13 further ticks leave an incomplete countdown: exactly 1 kg output, 250 J spent, one component wear application and 1 kg still reserved. The actual save control commits a native checksummed checkpoint containing complete production/tool/inventory records: original request/principal/tool/source/carrier binding, completed/remaining cycles, countdown, reservation, receipts, energy, component integrity/fractional wear and physical equipment/provenance.

The same running client sends a Cancel, then the host is removed before polling that request. Transport loss abandons this uncertain request without reporting success or retrying it. The replacement world loads the disk checkpoint; its only production change is `paused/restart`. Manual reconnect reauthenticates the original invite and receives fresh scoped data without transmitting abandoned or automatic extraction actions. Another 180 ticks preserve all paid records, countdown, reserve, output, wear and energy. A retained Start returns its receipt without applying work; a stale Resume rejects without mutation.

Two independent replacements load that same disk checkpoint. Explicit valid Resume retains the saved binding and completes exactly the remaining countdown (its acceptance tick advances one work tick). The final tick adds only the remaining 1 kg, spends only another 250 J and applies only one further wear cycle. Further idle ticks and retained Start cannot replay output. In the other branch, explicit Cancel releases only the unprocessed 1 kg to the original source; completed cargo/energy/wear remain. Retained Cancel and Start produce no further changes. Complete snapshot validation and integer conservation remain enabled through the inherited resource helper.

## Runtime gap retained within scope

A retained Resume retry after the job finishes is safely rejected with `No sustained extraction is reserved.` It does not return the previously retained successful receipt. `ProductionSimulationSystem.authorize_operation` checks job existence at the Resume guard before `apply_local` reaches its receipt lookup. The fixed-tick path therefore provides no transparent retained-success identity guarantee for this state, though the test proves no resource mutation or output replay. This differs from the intended repeat-result contract in `docs/design/persistence-and-command-boundary.md` and is reported to the Coordinator before any runtime expansion. This PR records the actual rejection; it changes no runtime or authorization contract.
