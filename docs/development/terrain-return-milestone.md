## Ownership and atomic return

`TerrainSimulationSystem` owns matter, escrow permissions and lifetime parcel lifecycle. `TerrainReturnCommand` runs synchronously at the next authoritative fixed tick, sharing the existing 16-attempt terrain ingress budget and priority 350. Return has independent authenticated principal ordinals 1-128 and ID `terrain-return-<ordinal>`. Its exact payload is `item_id` and `expected_inventory_revision`; no caller amount, provenance, definition, destination or identity is accepted.

A fresh return requires the existing world/region `terrain.operate` grant, registered inventory principal, voluntary consciousness, an unreserved manipulator and the exact inventory revision. The trusted inventory factory transaction verifies the exact prototype/revision and containment root against the authenticated body, including nested owned storage. A tray parcel or another body's parcel must first be acquired through normal inventory commands. Return requires no terrain cell, reach, shovel or free empty supporting hand; fill retains all existing work gates. No generic recycler interface is exposed.

Return consumes one whole legitimate parcel. The existing `prepare_equipment_change(..., false)` transaction validates a detached physical graph with complete prospective Production and Terrain masses. The bridge installs a prospective returned association and zero payload projection only for synchronous inventory adoption; adoption failure restores both. Successful adoption settles item removal, permanent return receipt and escrow assignment to the holder in the same call, with no await or later fallible mutation. No new inventory transaction API was necessary. Canonical owner matter, material revision and origin parcels do not change during return. Inventory/ledger/body revisions advance once, equipment binding is removed if applicable, and load caches derive from the adopted owner. Existing interaction revision rules invalidate conflicting timed work.

The same transfer ID then fills through the ordinary owner path, including partial fills. It belongs to the returner even if the original claimant was another principal. Cells plus all live owner transfers remain exactly the original 2 kg commissioning budget; historical receipts add no conserved mass. Production resources and component provenance are untouched.

## Lifecycle v3, immutable retries and migration

Terrain checkpoint v3 extends each of the existing at most 128 lifetime associations with an immutable detached **v1 claim receipt** and nullable permanent **v1 return receipt**. Claim receipt captures the complete transfer at materialization, which can be a remainder after ordinary escrow fill. Its mass/material/provenance never change. Return receipt pins returner, independent ordinal, item/transfer ID, original expected inventory revision and domain owner sequence at return. The latter places the permission handoff between retained excavation/fill operations.

An active association requires its exact complete canonical transfer and physical parcel. A returned association requires the physical parcel to be absent, contributes zero payload mass and may coexist with smaller returned escrow or no transfer after full fill. All associations and receipts remain forever within the existing lifetime ceiling. Returning a parcel does **not** release a slot. Returned transfer escrow is explicitly **fill-only**: neither the original claimant nor its new holder can materialize it again under a fresh ordinal. A later new excavation can create a different transfer, subject to the original lifetime budget.

Exact claim retry remains authenticated read-only reconciliation returning the same original v1 receipt, including after physical transfer, return, partial/full fill, receipt-tail eviction and restart. It never implies that the physical item is still present and never recreates one. Exact return retry similarly returns its retained receipt without rechecking current ownership/revision or doing physical work. Changed retained intent and skipped/expired fresh ordinals reject with no canonical mutation. Returned records keep original claim ordinals contiguous; return ordinals are separately complete, unique and ordered by inventory commits.

V1 migrates through the existing empty portable map without commissioning matter. V2 validates the canonical owner and exact old association shape, copies each complete immutable active transfer into its original v1 receipt and sets `returned: null`. Missing legacy links reject; existing parcels remain recoverable. V1/v2 schemas remain unchanged and the world envelope explicitly accepts v3. Saving normalizes association, receipt and return numbers. V3 needs the new runtime; blind rollback to a runtime that only accepts v2 cannot restore it.

Recovery verifies finite pinned material and exact origin parcels, active item/payload bijection, returned item absence, registered original claimants/returners, unique contiguous ordinals, monotonically ordered commit revisions and matching retained creation/removal factory receipts. Original claim amounts reconcile with retained excavation minus prior escrow fills; returned amounts reconcile with remaining escrow plus the complete post-return fill tail when retained. Chronology checks compare the recorded handoff with inventory revisions observed by retained terrain commands. Claimant rewind reverses return permission at its domain sequence boundary before replaying the earlier excavation/fill tail. Validation uses candidate payload owners and leaves the old world unchanged on rejection. Checkpoints remain trusted atomic records: these checks cannot authenticate fully rewritten history once bounded domain/factory tails have expired.

Profiling keeps existing commit/retry/rejection counters and adds `lifetime_claims` and `returned_parcels`; `portable_items` now counts live physical parcels. Work is bounded by 128 lifetime entries and the existing 64 domain receipts; no background garbage collection, extra tick work, I/O or async service is added.

## Transport, journal and Terrain panel

The existing invite-authenticated host codec constructs a distinct typed return command and binds the principal/session/world/region. Per-principal/per-session completion routing remains intact. Observation v3 includes only currently owned returnable parcels, next return ordinal, readiness/message, exhaustion and own `fill_only_transfers`. Legacy observation v1/v2 decoders remain supported without enabling return. The bounded decoder checks exact shape, stable parcel/transfer identity, material/provenance and total visible finite mass. No projection can import owner state.

Journal v3 stores return intent in the existing scoped 8 KiB one-unresolved-intent journal. V1 work and v2 claim journals remain valid and preserve their versions during retry. Original ordinal, stable item and expected inventory revision freeze before send; uncertain return blocks fresh or changed terrain work. Typed work/claim commands cannot masquerade as returns. Journal write failure prevents a send; post-ack freshness and clear-failure reconciliation retain the existing behavior. Host durability remains at its checkpoint cadence; a client journal is not a durable host save.

The Terrain panel selects stable carried parcel IDs and exposes **Return whole carried parcel to own escrow**. It disables fresh work while uncertain, uses the existing original-intent retry and shows returned escrow as fill-only. A removed selected parcel does not silently retarget another parcel. Bootstrap and other gameplay panels are unchanged. This is headless actual-button acceptance; graphical/human/VR/controller usability has not been verified.
