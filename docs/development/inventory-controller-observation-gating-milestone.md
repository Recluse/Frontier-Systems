# Inventory controller observation gating

## Contract and composition

The trusted same-process owner retains one `InventoryRuntimeCommandGate` for both commands and reads. Its existing one-shot `initialize(inventory, world, region, provider)` constructs the controller authority over that exact canonical runtime. Reads cannot inject another authority, body, principal, world, region or replacement runtime. The composing owner supplies live opaque `InventoryControllerToken` identities and server-created `AuthenticatedCommandContext` values, retaining exclusive ownership of bind/replace/revoke/pin/reconcile operations. Neither read nor command methods are transport authentication mechanisms.

The gate now exposes `own_inventory_observation(token, context, include_details = false)`, `world_inventory_observation(token, context)`, `local_grip_observation(token, context)`, `local_observation(token, context)` and `read_search(token, context, view_id)`. Each call derives its actor from canonical principal ownership, validates the token/context against that actor and the gate's composed scope, then synchronously invokes the corresponding existing scoped runtime method. Provider callbacks finish and canonical restore fencing is checked before projection. There is no automatic pin, binding, reconciliation, cached view, fixture fallback, broad snapshot or client-selected scope. The optional detail flag selects only the already authorized own-inventory projection. A search ID identifies a view; it grants no authority to its actor or target.

Own inventory, reachable world storage, own grip participation and own job/outcome status keep their existing read authorization without requiring voluntary action. Search additionally requires the existing voluntary capability, completed live view and current actor/target epochs, inventory revisions, physical reach and accessibility. No broader visibility or new payload schema is introduced. All returned dictionaries and nested arrays are detached. Presentation active-hand selection and movement remain separate work; this milestone installs neither.

## Owner, cadence, persistence, failure and profiling

Canonical state remains in `InventorySimulationSystem` and its shared inventory, body, grip and search owners. The composing server serializes trusted lifecycle transitions, restores, command application and synchronous reads on the same thread; no awaits, network callbacks or asynchronous continuation occur after validation. Reads observe current completed state on demand between fixed simulation ticks. Commands retain their next-tick application contract and priority 200 progress/completion cadence.

Gate, token and search identities remain volatile. Snapshot v4, restore generation fencing and all existing projection schemas are unchanged. Unreconciled restore blocks reads; explicit reconciliation retires all old identities, and identical saved epochs or a same-session fresh bind cannot revive an old token/view. Provider revocation is checked on every read. Missing, foreign, revoked or replaced tokens and invalid contexts fail with a null value before scoped dispatch. Successful reads conserve canonical snapshots, receipts, jobs, grips, items and outcomes. Existing scoped search reads can prune an expired/invalid volatile view according to their established contract; they never mutate canonical inventory.

Gate profiling adds one saturating `observations` counter for scoped dispatch attempts, including scoped method rejection, alongside existing `applications` and pre-dispatch `rejections`, bounded by `MAX_EXACT_INTEGER`. Authority counters remain separate. No view or payload is retained by the gate, and no configuration, dependency, example environment file, port or persistence migration is required.

## Acceptance and limitations

`inventory_controller_observation_test.gd` composes actual inventory and health runtimes and the same gate for commands/reads. It tests exact fresh projections and deep output detachment; own nested inventory, job, grip and completed-search actor isolation; denial matrices conserving canonical and volatile state; provider revocation with a live view; actor replacement/revocation; target lifecycle invalidation of a completed search; identical restore before/after reconciliation and same-session rebind; current world reach after separate internal movement; provider-callback restore fencing; and freed-runtime failure.

Run the versioned bounded headless runner with pinned Godot 4.7.2, this test and existing command gate/queue, authority/lifecycle, scoped search, inventory/self/world/grip and checkpoint regressions. `.github/workflows/ci.yml` discovers the new test on Windows and Ubuntu without workflow changes. Record exact local and CI results separately. Headless acceptance does not establish graphical, controller, VR, live-service, production network or deployed behavior. The component remains uninstalled in production admission and `WorldRuntime`; existing internal/development runtime reads retain their explicitly separate trusted fixture role. No merge, release, network rollout, artwork, provenance or license change is included; first-party changes are MIT.
