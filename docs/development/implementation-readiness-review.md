- The runtime split is sound: Godot owns real-time physical simulation and applies validated commands on fixed ticks. PHP owns asynchronous control-plane, account, persistence, and provider services. DiscordPHP and Steam are adapters, not sources of world authority.

These are contract foundations; installation, radio reception, wired pulse delivery, and action/alarm/message handlers are not implemented. ## Current implementation boundary

The current result is a local prototype slice, not a multiplayer game. A main scene and bootstrap select client or headless-host mode, create the simulation runner, and show a code-generated pressure/airlock control panel. Headless startup passed locally on Godot 4.7.2 for Windows; graphical presentation has not been checked. The pressure model is intentionally limited to three fixed-volume, equal-temperature ideal-gas compartments. Pressure and access-control snapshots can be serialized and restored before the runner starts, but nothing writes or loads them from disk or PHP yet. There is no player movement, habitat geometry, network session, durable world record, database integration, blueprint loader, or persistence/reconnect flow. Bypass tools are synthetic IDs supplied by the local development context; production inventory/equipment, spatial checks, real ACL evaluation, mechanical force/pressure failure, and repairable bypass faults remain unimplemented. Steam remains optional and is not initialized by the bootstrap. The PHP service currently reports its own health and uptime; it does not yet provide game identity, persistence, Discord, Steam authentication, or LLM functionality.

The core async design keeps promise callbacks out of physics callbacks, and both the simulation command queue and promise dispatcher now have capacity limits. A full promise queue rejects the affected continuation with a typed `ServiceResult`; command-queue saturation also returns a typed failure. The wire `CommandEnvelope` deliberately contains no actor identity; an authenticated request and server-local command context carry the principal separately. The demo uses a development-only local context, not real authentication. Request ID/world scope rules and snapshot compare-and-swap/idempotency contracts are now codified, but there is no durable command receipt journal, network ingress, or snapshot repository adapter yet.

The current profiling snapshot reports tick and system totals/maxima. It does not yet provide history, percentiles, captures, or client/server profiles. CI is configured to import the Godot project and start the bootstrap headlessly on Ubuntu and Windows, and to run the small PHP suite. It does not yet exercise gameplay rules, multiplayer, persistence, or a networked production server. The only current PHPUnit test covers runtime metrics.

## Next implementation and review gates

### Before persistent-world and account implementation

1. **Contract implemented, runtime auth pending:** `CommandEnvelope`/`command-intent-v1` contain no actor field; `AuthenticatedCommandRequest` and `AuthenticatedCommandContext` bind a principal after transport authentication. The remaining work is the real session/permission provider, registered command handlers, target ACL checks, request receipt ledger, rate limits, and durable replay/restart behavior before accepting clients.
2. **Connect the snapshot contract to durable PHP persistence.** Compare-and-swap revisions and idempotent snapshot-write IDs are now defined. Still define migration policy, transactional checkpoint acknowledgements, recovery behavior, retention, and backups, then implement a genuinely asynchronous storage adapter. Keep I/O outside the Godot tick and preserve the current restore-before-start gate.
3. **Add entity and actor records before broadening gameplay.** Keep Godot scene nodes as views/adapters. Specify region ownership, player/principal/body separation, reconnect leases, and safe unload rules before persistent multiplayer or procedural region work.
4. **Grow the pressure slice behind its current contracts.** Add reusable volume/network definitions, leaks, pumps, and liquid behavior only with documented units and conservation assumptions. Keep the current ideal-gas solver as a low-fidelity model; do not let production thermal/species behavior depend on demo constants.
5. **Keep community and official hosting on one server contract.** The local headless mode uses the same `WorldRuntime` as the client. Account bootstrap, backups, operations, and production persistence remain separate deployment work rather than a second simulation implementation.

### Before external service adapters

5. **Keep asynchronous adapters bounded.** The dispatcher now has a configurable capacity and explicit overflow rejection. External request adapters still need documented deadlines, cancellation, and error semantics. No callback may block a tick or mutate canonical state directly.
