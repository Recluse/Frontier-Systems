# World context labels

Refinery/workstation, resource-source, terrain-cell and storage-tray text uses `WorldContextLabel`: a disposable world anchor and observed text, with one shared layout owned by its viewport. Canonical production, terrain and inventory systems retain ownership. This presentation has no persistence, schema, commands, collision or service I/O. Shared-layer installation is deferred until nested viewport setup finishes; successive anchors reuse the existing named layer. Destroyed anchors cancel their pending call before allocation, and the viewport owns layer teardown.

At each rendered frame, the layout projects visible targets through the active camera. Behind-camera/offscreen/explicitly hidden targets disappear. It considers at most 40 targets (32 projected storage roots plus the existing fixture labels), displays at most eight complete cards and searches fourteen nearby placements per candidate. Opaque 264-pixel cards wrap their complete identity/value/instruction text, remain inside a 12-pixel margin, avoid one another and reserve the inventory selection card's existing maximum top-right rectangle. Layout prioritizes targets nearest screen center; cards with no suitable placement within 320 pixels of the anchor disappear until camera movement or available space permits them. Very narrow viewports hide context cards instead of truncating instructions.

Leaders terminate at the existing display proxies: tray surface, resource mesh center, workstation surface or advisory terrain marker. Those fixture display offsets are not canonical physical item poses. Visibility means only camera framing and layout space; it does not assert line of sight, occlusion or authoritative reach. Existing overlays remain the full actionable source when context is suppressed.

All controls ignore mouse input. Native pick areas, selected item identity card/leader, selection handlers and command validation remain unchanged. Removed targets retire their cards; observation rebuilds and parent visibility changes are honored on the next frame. Profiling is opt-in through existing engine tools; `shown`, `cards` and `anchors` expose bounded presentation counts for checks without affecting simulation.

Headless layout checks are in `world_context_label_test.gd`; the existing inventory preview and first-playable interaction checks cover the command bridge. Graphical acceptance requires the actual root-window capture route documented in the milestone.
